Edge Board

Every market is priced against a sharp reference line with the vig removed. The board shows the best price you can get and how far it beats fair. Rules run before anything reaches the card.

MarketPickFairHard RockDKFDMGMEdgeStakeRules

Fair = sharp-book two-way line with the margin removed proportionally. Edge = fair win probability × best decimal price − 1. Stake = fractional Kelly, capped at 2 units. All odds on this page are invented for the prototype.

Tonight's Card

The card is what you two actually bet. Every leg passes the rulebook, stakes come from the edge, and it locks before tip so closing-line value can be graded.

Pre-lock checks

Checks are hard gates. A failed check blocks the lock until the leg is removed or the rule is changed in the Rulebook.

Rulebook

Rules start as hypotheses. A rule moves to Confirmed only after enough graded bets and positive CLV, and gets retired when the data turns against it. Claude enforces the Confirmed set and proposes changes after each night.

Ledger & CLV

Win rate lies over small samples. Closing-line value is the faster signal: if your price consistently beats where the line closes, the edge is real before the results catch up.

Game Plan

How this becomes a real agent the two of you run locally, and where an NBA edge can realistically come from.

The nightly loop

IngestOdds from every book + sharp line, injuries, lineups, rest, schedule
PriceDe-vig the sharp line, adjust for late news, compute fair odds
ScreenRank by edge, apply the Confirmed rules as hard gates
CardClaude assembles the card, sizes stakes, explains each leg
GradeCapture closing line + result, compute CLV per bet
LearnWeekly review promotes, demotes or retires rules

Where the edge actually is

Strongest
Price, not picks. Compare every number to a de-vigged sharp line and only bet when a book is off. This is the one approach that works without predicting anything.
Strong
Speed on injury and lineup news. NBA props move hard when a starter is ruled out. Watching official injury reports and beat reporters, then hitting stale prop lines in the minutes before books adjust, is the most repeatable NBA-specific edge.
Moderate
Player props over sides and totals. Spreads and totals on national-TV games are the sharpest markets in sports. Role-player rebounds, assists and threes are priced with less care.
Moderate
Situational spots. Back-to-backs, travel, rest disadvantage and early-season rotation changes. Useful as rules, but markets price most of this already.
Weak
Parlays and same-game parlays. They stack the book's margin on every leg. Treat boosts as the only reason to touch one, and check the boosted price against fair first.

Florida reality check

Line shopping is the biggest lever, and in Florida the only regulated sportsbook is Hard Rock Bet. The DK, FD and MGM columns are useful as price references even where you can't bet them, and they tell you when Hard Rock is the outlier.

Prediction-market exchanges list NBA contracts too, but their legal status in Florida is being contested. Check before funding one.

Ground rules for you two

  • Fixed bankroll you're both fine losing. Stakes come from it, never from new deposits.
  • Paper-trade the first two weeks. Grade CLV before any real money.
  • Claude is the rules clerk and the analyst, not the oracle. No leg goes on the card without a priced edge.
  • Stop rule: if CLV is flat or negative after 150 bets, the edge isn't there.

Build phases

Week 1 · now → Oct 20
Data spine. Odds API pulls for NBA game lines and props from a sharp book plus the US books, the free nba_api package for box scores and schedules, and a SQLite database. Snapshot odds every few minutes so closing lines are captured automatically.
Week 2
Pricing + edge board. De-vig engine, best-price finder, fractional Kelly sizing. This page becomes the real front end, served locally and reading from the database.
Week 3
Claude agent. A Claude API agent with tools for the board, injuries, the ledger and the rulebook. It builds the card, writes the reasoning for each leg, and enforces Confirmed rules as code checks it can't talk its way past.
Week 4
Injury watcher + alerts. Poll official injury reports and push a phone alert when a starter is ruled out and props haven't moved yet.
Weekly after
Rule review. Claude reads the week's graded bets, proposes rule promotions and retirements with the numbers behind them, and you two approve or reject.

Local stack

  • Front end: this UI as a Vite + React app on localhost:5173.
  • Back end: Python FastAPI for odds ingest, pricing and the ledger, with SQLite.
  • Agent: Claude API with tool use, rules stored as versioned JSON that code enforces and Claude can propose edits to.
  • Jobs: a scheduler for odds snapshots every 5 minutes on game days and the closing-line grab at tip.
  • Shared: both of you open the same local URL over your home network, or deploy to a small private server later.
